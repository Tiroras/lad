# Лад

«Лад» — приложение для личных финансов на **iOS и Android** с русским интерфейсом. Помогает вести доходы и расходы, планировать бюджет и накопления, оценивать доступную сумму на день и проверять покупку в прогнозе. Web используется для предпросмотра общего интерфейса и браузерных тестов.

Поддерживаются счета в разных валютах, переводы, цели, регулярные платежи, долги, аналитика, импорт CSV и резервные копии.

**Стек:** React Native, Expo SDK 58, React и TypeScript. Версии зависимостей зафиксированы в `package.json` и `package-lock.json`.

### Как считаются деньги

«Можно потратить» учитывает фактические деньги повседневных счетов, обязательства, взносы на цели и резерв, затем проверяет дальнейший прогноз. Ожидаемый доход, накопления и кредитный лимит не прибавляются к доступным деньгам.

### Ограничения

Учёт хранится локально: сервера, банковских подключений, облачной синхронизации и реальных списаний нет. Нативное хранилище зашифровано; Web и экспорт JSON — без шифрования.

## Запуск

Нужен **Node.js 22.21.1** из [.nvmrc](.nvmrc). Команды выполняются из корня проекта:

```sh
npm ci          # установить зависимости из lock-файла
npm start       # запустить Expo dev server
```

| Команда           | Назначение                                                |
| ----------------- | --------------------------------------------------------- |
| `npm run web`     | Открыть веб-предпросмотр                                  |
| `npm run ios`     | Собрать и запустить iOS-приложение; нужны macOS и Xcode   |
| `npm run android` | Собрать и запустить Android-приложение; нужен Android SDK |

Для нативного запуска подготовьте симулятор, эмулятор или подключённое устройство. Через `npm start` также можно открыть проект в совместимой с SDK 58 версии Expo Go.

### Деморежим по явной опции

`npm run start:demo` или `npm run web:demo` включает отдельный профиль с примерами. После первоначальной настройки выберите **Профиль → Профили → Демо**. Экспорт с демоданными: `npm run build:demo`.

### Запуск с нуля

`npm run start:fresh` или `npm run web:fresh` открывает приветствие, **удаляя локальные данные всех профилей без резервной копии** при каждом полном запуске или Reload. Используйте только для изолированных тестовых данных. Режим действует в разработке; для сохранения данных между запусками вернитесь к обычной команде.

## Проверки и сборка

| Команда                    | Назначение                                       |
| -------------------------- | ------------------------------------------------ |
| `npm run typecheck`        | Проверка типов TypeScript                        |
| `npm test`                 | Модульные и архитектурные тесты                  |
| `npm run test:e2e`         | Playwright в режимах Demo, default и Fresh       |
| `npx expo install --check` | Проверка совместимости зависимостей Expo         |
| `npm run build`            | Экспорт JavaScript и ресурсов iOS, Android и Web |

Перед первым запуском Playwright установите браузер: `npx playwright install chromium`. Команда `build` не создаёт APK/IPA.

### Мобильные тесты из терминала IDE

Нужны Android SDK, созданный эмулятор, Java 17+ и Maestro CLI. `npm run emulator` запускает эмулятор; следующая команда собирает Android release, устанавливает приложение и выполняет сценарий:

```sh
npm run test:mobile -- path/to/flow.yaml
```

Замените путь существующим YAML из `tests/mobile/` и подготовьте режим, дату и данные по его плану в `tests/mobile/plans/`. Для Demo добавьте перед командой `EXPO_PUBLIC_ENABLE_DEMO=true`; Fresh требует отдельного запуска в разработке. Справка по запуску через Docker: `docker compose run --rm android --help`.

## Структура проекта

```text
App.tsx                 точка входа интерфейса
index.ts                регистрация приложения Expo
src/
├── application/        сборка приложения, провайдеры, навигация и оболочка
├── screens/            экраны обзора, операций, плана и аналитики
├── features/           модули счетов, целей, бюджетов и других функций
├── domain/             финансовая модель, чистые расчёты и проверка данных
│   └── actions/        проверяемые изменения финансового состояния
├── state/finance/      единое состояние и сохранение учёта
├── infrastructure/     адаптеры хранилища, шифрования, файлов и уведомлений
└── shared/             общие UI-компоненты, тема, функции и хуки
tests/                  модульные и архитектурные тесты
├── e2e/                браузерные сценарии Playwright
└── mobile/             сценарии и планы проверок Maestro
assets/                 иконки и графические ресурсы
scripts/                инструменты разработки и проверок
docker/                 настройки контейнерного окружения
.github/workflows/      автоматические проверки CI
```

Экраны собирают компоненты из `features`, финансовые правила находятся в `domain`, платформенные API — в `infrastructure`. Границы модулей проверяются в `tests/architecture.test.ts`.

Скрипты `scripts/capture*.mjs` сохраняют снимки в игнорируемый каталог `test-artifacts/screenshots/`. Скрипт `scripts/capture.mjs` также пересоздаёт иконки приложения. Пример CSV для проверки импорта находится в `tests/fixtures/statement.csv`.

## Удаление профилей и данных

**Профиль → Профили** позволяет удалить отдельный профиль, а **Профиль → Данные и копии → Удалить все профили и данные** — весь локальный учёт. Оба действия требуют ввода `УДАЛИТЬ`; заранее сохраните нужную копию.
